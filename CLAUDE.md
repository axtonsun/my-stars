# my-stars

Static site that shows the owner's GitHub stars grouped by purpose. Deployed to GitHub Pages by `.github/workflows/sync-and-deploy.yml` (daily cron, on push to `main`, and manual dispatch).

- `data/stars.json`: written by `scripts/sync_stars.py` in CI. Never edit by hand. CI only commits it when stars are added or removed.
- `data/classification.json`: hand-maintained. `categories` (id → `glyph`/`name`/`desc`/`name_en`/`desc_en`; `glyph` is the one character used in call numbers like 研·02, kept in both languages), `groups` (drawer order, each lists category ids), `tags_en` (Chinese tag → English name), and `repos` (full_name → `cat`, `tags`, `summary`, `summary_en`). Tags are stored once, in Chinese where they are Chinese; the site shows the `tags_en` name in English mode, so filtering and links work the same in both languages. Tags describe what a repo is about, never the language it is written in. Each drawer's tabs (guide cards) are made from tags only: every tag at least two of its cards share, most used first, with no upper limit. There are no language tabs; the card shows the GitHub language and search finds it.
- `site/`: vanilla HTML/CSS/JS with no build step and no external resources (the owner is in China, so no CDNs or Google Fonts; fonts are self-hosted in `site/fonts/`). It reads both JSON files at runtime. The UI is a card-catalogue cabinet: one drawer per category, one card per repo. `draw.js` draws the cabinet as hand-drawn SVG, `app.js` handles state (kept in the URL hash: `c` drawer, `t` tag, `s` sort, `q` search, `r` repo, `l` language), and `i18n.js` holds the interface text in Chinese and English. A starred repo with no entry in `classification.json` goes into the built-in `inbox` (「待归档」). A drawer opens by a click (it slides all the way out) or by dragging its handle (it stays where it is let go; a flick sends it all the way out or in; let go under a quarter of the way out, it shuts). How far each drawer is out is kept in `app.js` (`OUT`, `LEFT`), not in the URL. Dragging a foot in towards the middle lifts that side of the cabinet; let go, it drops, bounces once and the drawers rattle (CSS transforms and Web Animations: `Draw.tipped`, `follow()` and `drop()` in `app.js`). The pencil textures are SVG filters, which are slow to draw, and the browser draws the whole cabinet again on every frame it turns, so the parts that never change (the carcass, and each drawer front but for its words) are drawn once into pictures (`Draw.bake`, during the loading animation) and the cabinet shows those. Keep new filtered drawing out of the cabinet, or put it through `art()` in `draw.js`. On opening, the page shows a small cabinet whose drawers come out in turn (`Draw.loader()`) for at least 3 seconds, on purpose (the owner asked for it), while the data loads.
- The site is bilingual. With no `l` in the URL it uses the language the visitor picked last (saved in the browser), else the browser's language (Chinese if any preferred language is Chinese, otherwise English); the 中文 / EN switch in the header changes it. Search matches both languages either way. Interface text lives only in `i18n.js`: add every new string there in both languages instead of writing it into `app.js` or `draw.js`.
- `README.md` (Chinese) and `README.en.md` (English) say the same thing. When a change makes one out of date, update both.

The owner writes in Chinese. Write summaries and tags in Simplified Chinese, and also write the English versions (`summary_en`, plus a `tags_en` entry for every new Chinese tag).

## When asked to 「更新分类」 / classify new stars

1. `git pull` first. CI may have committed a newer `data/stars.json`.
2. Run `python3 scripts/check_classification.py`. It lists `UNCLASSIFIED` repos (need entries) and `NOT STARRED` entries (the owner unstarred them, so delete them).
3. For each unclassified repo, read its description and topics in `data/stars.json`. If the description is empty or unclear, fetch the README from `https://raw.githubusercontent.com/<owner>/<repo>/HEAD/README.md`. The GitHub API for other repos is not reachable from cloud sessions, but raw.githubusercontent.com is.
4. Add an entry: pick an existing `cat`, write 1–4 short `tags` (reuse existing tag spellings, such as `Agent Skill`, `论文写作`, `HyperLogLog`, `面试`), a one-line Chinese `summary` of what the repo is for, and a one-line English `summary_en` that says the same thing (a translation of the summary, not a copy of the GitHub description). Don't tag the language the repo is written in (`C++`, `Go`, `Python`…): the card already shows the language GitHub reports, and search finds it. A language name is a tag only when it is what the repo is about or what it produces, and GitHub reports another language or none (`cpp-best-practices/cppbestpractices` is a C++ guide written in Markdown; `answer-me-with-html` writes HTML pages). For a new Chinese tag, add its English name to `tags_en`, in Title Case like the existing ones; tags that are already English need no entry.
5. Only add a new category when several repos clearly don't fit any existing one. Add it to `categories` (with `name_en` and `desc_en`) and to a group in `groups`. Keep `name_en` short: it is drawn on a drawer label, which fits about 15 Latin characters per line on two lines.
6. Re-run the check script. It must exit 0. Besides unclassified and unstarred repos, it fails on missing English text (`NO ENGLISH`), on `tags_en` entries no starred repo uses any more (`UNUSED TAG`, delete them), and on tags that repeat the repo's own GitHub language (`LANGUAGE TAG`, delete them). Then commit and push to `main`, which redeploys the site.

To preview locally, copy `site/` and `data/*.json` into one folder (`data/` next to `index.html`) and serve it with `python3 -m http.server`.
